On a phone, these are successive screens: folders → conversations → messages. On a PC, you can see all three together.

Do I have to add each project?

No, that should be automatic for folders found in your connected Codex and Claude history. Both keep local session records that contain folder information. There is no single shared directory, so cestOn would combine the two.

Connect your PC once. After that, new folders should appear as you use them. Use New conversation to start in General, or select a folder when your request needs files. This additional flow is proposed.

What appears in the conversation panel?

The original conversation: your prompts and the provider’s replies. The title should come from Codex or Claude where available. It is not a new summary written by cestOn.

An optional “Catch me up” summary can come later. This preview does not copy your messages or titles; it uses neutral labels for real records.

What does “most recent” mean?

Conversations are ordered by their latest recorded activity. Each folder takes the date of its most recent conversation. Clicking a folder to look at it should not change that order.

This snapshot uses saved event dates for Codex and last-modified dates from Claude. Claude’s date is an approximation of activity; it does not tell us whether an agent is running.

Can I use it while away?

The intended flow is to open cestOn on your phone and continue here. Your PC does the work, so it needs to stay awake and connected, with secure phone access set up once.

That complete phone-to-existing-conversation flow has not passed acceptance yet. Discovery is useful progress, but it is not enough to call the daily workflow finished.

What was actually checked?

What this proves, and what it does not

No prompts were sent. No session was resumed. No project, provider setting or background service was changed. This file is a fixed snapshot, not a live connection.

The earlier application passed 106 automated tests using test environments. Those results do not certify this revised experience with your running Codex/Claude sessions or a physical phone. The new checks verify discovery and this prototype’s navigation.

Why did the previous preview say “Observe only”?

It meant “cestOn can read this saved conversation, but cannot send a reply to it.” That is a limitation of the connection, not something you should need to understand or configure every day.

The clearer message is “Can’t reply to this conversation”, followed by a reason. Reading history needs no vendor remote-control session. Sending a prompt needs a working connection to the correct running conversation.

You should not need to switch into Claude Remote Control or another app for the normal cestOn workflow. Whether cestOn can deliver that for your existing Codex and Claude sessions still needs to be established. If it cannot, we must say which sessions it supports rather than quietly starting a different one.

What is deliberately left out?

Related-session suggestions, AI summaries, task creation and technical connection settings. They distract from finding a folder and returning to a conversation. Scheduled-job filtering remains to be verified; this snapshot is not proof that every record is human-started.

This revises the proposed experience only. The current application has not been redesigned.
