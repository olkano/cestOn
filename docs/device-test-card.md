# Physical device acceptance card

Run this card against an isolated HTTPS installation. Browser emulation and fake audio do not complete it. Keep filled records under private acceptance evidence.

| Field | Record |
|---|---|
| Build / static bundle | Pending |
| Device model / OS / browser version | Pending |
| Dedicated HTTPS origin / date | Pending |
| Paired device alias | Pending |
| Install icon / standalone launch | Blocked until a physical device is available |
| Dark/light, portrait/landscape, keyboard | Pending |
| Actual microphone, editable transcript, cancel, denial | Blocked until a physical device and permission are available |
| Actual read-aloud and lock/unlock behavior | Pending |
| Generic push on locked device, duplicate tap, stale decision | Blocked until an enrolled device and configured push keys are available |
| Offline draft, close/reopen, reconnect, explicit send | Pending |
| Revocation clears access and private drafts | Pending |
| Test subscription/audio/installation cleanup | Pending |

Use the detailed procedure in [manual mobile acceptance](../zz_Specifications/09-acceptance-tests.md#manual-b-phone-installation-and-operation). Record actual failures and unavailable permissions; do not convert them into passes.
