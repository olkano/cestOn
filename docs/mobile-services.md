# Mobile services

The production build includes an asset-only service worker and the supplied launcher icons. Serve the UI and API from one dedicated HTTPS origin. The loopback development exception is local to the host; an HTTP LAN address is not a phone installation target. [Device acceptance](device-test-card.md) remains a separate physical check.

Unsent drafts and unresolved delivery identities use per-installation/device IndexedDB records with a 24-hour expiry. Reconnect refreshes state and does not send a draft. Retrying an unresolved command uses its original key and payload. Revocation clears the application's private drafts. No authenticated API response, audio, provider history or evidence is cached by the worker. Updates wait for compatible host readiness, the matching static bundle, no active voice capture and no unsent transition. Only cestOn cache namespaces are pruned; three static generations remain available.

Push-to-talk negotiates the browser's recording format, converts locally to canonical mono 16-bit 16-kHz PCM WAV, and uploads only after stopping. The server independently validates the WAV header, byte count and maximum 60-second duration. Audio stays in request memory and is not written to a temporary file. Cancel or failed speech leaves text usable; transcripts remain editable and unsent. Read-aloud uses browser speech synthesis after a tap. No background microphone or locked-phone playback guarantee is made.

Configure speech locally with `voice.enabled`, an explicit model, a full HTTPS transcription endpoint and an optional `CESTON_SPEECH_*` credential reference. The endpoint accepts multipart fields `file` (WAV) and `model`, and returns JSON with a string `text`. Requests have a 45-second timeout, no redirect or automatic retry. Extra response metadata is ignored. Do not use a coding-provider credential variable for speech. Missing configuration leaves the capability unavailable; no paid service is enabled automatically.

In-app notifications persist independently of push. Configure push locally with an explicit subject, public VAPID key and a separate `CESTON_PUSH_*` private-key reference. Subscription permission requires a tap. Secrets are protected with Windows DPAPI under the installation owner, so moving encrypted state to another OS identity requires re-enrollment. Allowed push endpoint hosts are `fcm.googleapis.com`, `updates.push.services.mozilla.com` and `web.push.apple.com`; other services require an audited host allowlist change. Generic payloads deep-link to current work after authentication and never approve an action. Transient delivery is capped at three attempts; 404/410 disables the subscription. A crash during submission stays uncertain, and submitted never means seen.

Implementation references: [Web Push library](https://github.com/web-push-libs/web-push), [WebKit Home Screen and notification behavior](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/). Actual supported versions and device results belong in the evidence ledger.
