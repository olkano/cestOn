# Set up your own installation

Use the pinned Node version in `.node-version`, npm 11 and Windows x64 from the owner's normal unelevated terminal. An elevated token can assign new files to Administrators instead of the owner's SID, which the private-state check rejects. Clone the source, run `npm ci --ignore-scripts`, then `node scripts/check-native.mjs` to verify the distributed SQLite binary and `npm exec -- playwright install chromium` for browser checks. Run `npm run verify`, `npm run test:security` and `npm run test:updates`. No sibling repository is required. The [support matrix](support-matrix.md) distinguishes tested fixtures from blocked native and physical-device gates.

For a disposable demonstration, run `npm run dev` and use its one-use pairing invitation. This installation contains clearly labelled synthetic providers and disappears when stopped. Its HTTP loopback origin is for the host browser; it does not establish phone installation or remote access.

For a new owner installation, extract the verified Windows bundle and open `Start-cestOn.cmd`. Choose whether to connect the local Codex and Claude history folders. Pair the browser using the one-use code shown by the launcher. It starts the PC app on port 4318. See [the first-use guide](first-use.html).

For a custom setup, copy [the empty configuration](config.example.json) outside the checkout and choose an absolute data root outside Git, synchronized folders and registered projects. Set `history.codexHome` or `history.claudeHome` to the absolute provider home to allow browsing that source. Run the unpacked bundle's `node dist/apps/supervisor/src/cli.js init --bundle . --config CONFIG --root DATA`. It leaves the installation stopped. Follow [operations and recovery](operations.md) for temporary start, pairing, doctor, backup, startup registration and exact stop scope. To connect history after first setup, stop the installation before editing its config, then restart. The launcher opens the default loopback port. Use your configured address for a custom port or origin.

For saved-chat replies, set `history.codexExecutable` or `history.claudeExecutable` to the absolute path of the corresponding signed-in provider executable. The verified Windows versions are Codex CLI 0.160.0 with ChatGPT sign-in and Claude Code 2.1.325 with subscription sign-in. Chat replies use these local applications directly and need no cestOn Windows execution-host setup. When the provider holds a conversation open, cestOn queues the reply for that same session and sends it automatically once the session is free. Use Work for file changes.

Register projects by editing the external configuration while stopped. Each needs a UUID, display name, absolute canonical root, `git` or `documents` kind, provider ID, explicit operations and known verification recipes. Recipes use an executable and argument array; shell strings are not accepted. A project registration never grants authority over its sibling folders. Give a changed project root or execution policy a new project ID; existing task scopes stay bound to their accepted configuration.

Native profiles need an explicit executable, the supported version, a dedicated authenticated provider home, observed billing mode and a constrained profile. Subscription access is not guessed from a configured string. Metered Claude work needs a spending ceiling; metered Codex work remains blocked because this integration cannot enforce its monetary cap. Set the assistant provider separately. Keep authentication in the provider's managed home and use environment references for optional speech/push credentials. Do not put secrets into JSON configuration. See [provider certification](provider-compatibility.md).

For phone access, provision a dedicated HTTPS origin and reverse proxy as a separate authorized operation. Keep the actual listener on loopback, forward the expected public Host unchanged, allow SSE and set `publicOrigin` to that exact origin. Pair each device independently. Run [the physical-device card](device-test-card.md); an emulated viewport is not a phone installation test. No existing tunnel or account is configured by setup.

For a Cloudflare Access installation, you can replace the manual device code with Cloudflare sign-in. Set `cloudflareAccess.team` to the Zero Trust team name, `cloudflareAccess.audience` to the cestOn Access application’s AUD tag, and `cloudflareAccess.ownerEmails` to the exact allowed addresses. Keep the hostname’s Access policy and tunnel JWT check enabled. After Cloudflare authenticates the browser, cestOn verifies the signed identity and starts its own browser session automatically. A lost device should also be signed out from Cloudflare Access.

Native execution and automatic local updates stay disabled until the installed host has the required live evidence. Enabling `requestedLocalApply` alone does not bypass certification, scope, regression, protected-change or rollback checks. Public redistribution also requires the owner's license choice and release review.
