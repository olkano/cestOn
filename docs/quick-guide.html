What is a “synthetic workspace”?

A practice folder, with simulated results.

What you see now

Synthetic workspace = demo project

It is a temporary folder created for trying the app. A fake worker produces a predefined result. It is not your repository, and stopping the demo removes its task data.

For your actual work

Project = a folder you register

For example, C:\Projects\my-repo. A repository is a folder with Git history; an ordinary documents folder can also be a project. A worker is the configured Codex or Claude connection that does the work.

Where do I select my repository?

Register the folder on the PC first. Then select its name in a task.

You have not missed a button. There is currently no “Add project” screen or folder picker. Settings lists projects, but registration is still a configuration-file step.

On the PC

Register the full local path.
C:\Projects\my-repo

→

In cestOn

Work → New task → Project
Select the registered display name.

  1. Use a saved installation, not the disposable demo.

    Its data folder stores tasks and configuration separately from your repositories.

  2. Stop that installation and back up its configuration file.

    Edit DATA\state\config.json on the PC. DATA is the saved installation's data folder, for example %LOCALAPPDATA%\ceston.

  3. Add your folder to the projects list, then restart.

    Use an existing local folder, a unique project ID and a configured worker. A GitHub URL alone does not tell cestOn which folder on your PC to use.

3

Install once. Open it like an app.

There are two parts: the Windows host and the app icon you use to reach it.

Windows: saved host first, app icon second

  1. Prepare a verified bundle and a saved data folder.

    Use a verified artifacts\ceston-… bundle, or build one with npm run package:local. The current release uses Node 24 and a local setup procedure; there is no one-click EXE installer. Owner installation setup.

  2. Configure your folders and real workers.

    The empty configuration has no projects or workers. Dedicated provider login and sandbox checks must pass before real Codex/Claude tasks can run. Provider setup and certification.

  3. Start the saved host, then open its address.

    The default PC-only address is http://127.0.0.1:4318. Generate a pairing code in a private terminal and connect the browser. This starts the installed app without the development server.

  4. Add an app icon in Chrome.

    Open the running app, then use ⋮ → Cast, save, and share → Install page as app, or the address-bar install icon when offered. Pin the installed app to your taskbar if you wish. Chrome instructions.

Show the one-time initialization and daily launcher

Example paths below must be replaced with your actual unpacked bundle and prepared configuration. Run PowerShell as your normal Windows user. Initialization requires an empty data folder; skip it for an existing installation.

One time · after configuration is ready
$Bundle = "C:\Apps\cestOn"
$Data = Join-Path $env:LOCALAPPDATA "ceston"
node "$Bundle\dist\apps\supervisor\src\cli.js" init --bundle "$Bundle" --config "C:\Setup\ceston-config.json" --root "$Data"
node "$Bundle\dist\apps\supervisor\src\cli.js" start --root "$Data"
node "$Bundle\dist\apps\supervisor\src\cli.js" pair --root "$Data"

For daily use, save the following as Start-cestOn.cmd and double-click it. Adjust the bundle path. This example uses the default PC-only address; use your configured HTTPS address if one is set.

Daily · after initialization
@echo off
node "C:\Apps\cestOn\dist\apps\supervisor\src\cli.js" start --root "%LOCALAPPDATA%\ceston"
if errorlevel 1 (
  pause
  exit /b 1
)
start "" "http://127.0.0.1:4318"

A browser app icon opens the interface; the launcher starts the host. Automatic sign-in startup is a separate setup step and is not enabled by a normal start. Start, stop, startup and backup commands.

An app icon does not start a stopped Windows host. Keep the host running, use the launcher, or deliberately configure automatic startup. Persistent sign-in/reboot acceptance is still pending.

Android: open your host's HTTPS address

Windows host runningReachable HTTPS addressChrome
  1. Set up phone access to the saved host.

    A dedicated HTTPS address and reverse proxy must be configured first. The demo does not create this address. Phone-access prerequisites.

  2. Open that HTTPS address in Chrome on your phone.

    Connect using a fresh one-use pairing code generated on the PC. Give the phone its own device name.

  3. Install the icon.

    In Chrome, use ⋮ → Install and create shortcut → Install. On versions with different wording, look for Install app or Add to Home screen, then follow the prompts. Chrome instructions.

  4. Launch from the new icon.

    If the installed window asks to connect again, pair that window with a new code. The Windows PC still does the work.

Do not type 127.0.0.1 on the phone. That means “this phone,” not your PC. Physical Android installation, microphone and push delivery still require device checks.

iPhone: add the host's web app to Home Screen

Windows host runningReachable HTTPS addressSafari
  1. Set up phone access to the saved host.

    A dedicated HTTPS address and reverse proxy must be configured first. The demo does not create this address. Phone-access prerequisites.

  2. Open that HTTPS address in Safari.

    Use a fresh one-use pairing code generated on the PC. Give the phone its own device name.

  3. Use Share → Add to Home Screen.

    Turn on Open as Web App if shown, then tap Add. Apple instructions.

  4. Open the new cestOn icon.

    If the installed app asks to connect again, pair it with a new code. Keep the Windows host awake and reachable.

The icon is the web app, not an App Store download. Physical iPhone installation, microphone and push delivery still require device checks. 127.0.0.1 on the phone cannot reach your PC.
